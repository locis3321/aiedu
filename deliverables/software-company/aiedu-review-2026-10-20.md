# 数芽（AI Edu）产品落地性审查报告

> 审查日期：2026-10-20 ｜ 审查方式：三视角交叉（产品/市场 × 架构/工程 × 代码实测）＋ 主理人定量盘点  
> 用户核心问题：**"设计一直无法落地"——为什么？往哪改？**

---

## 0. TL;DR

**这个项目不是"执行不到位"，而是：在一个法律上无法上线的承载形态上，为一个 2026 年已失效的差异点，用一套自杀式门禁和 169:1 的文档/代码比，搭建一个没有付费者的商业产品。**

三份独立审查的结论高度一致，且互相验证：

1. **后端是"真的"**（工程师实测）：uvicorn 8 秒启动、`run_pipeline("16+8")` 零 LLM 产出 5 节点核验课程、单元测试 215/217、e2e 11/12、Playwright 9/9、ruff 全绿。**代码质量不是问题。**
2. **但产品链路物理不可达**（架构师核查）：从"孩子输入一道新题"到"看到一节课"，被三个硬断点卡死——前端课堂页零 API 调用（小程序 lesson 页仅 1 行 localhost URL，H5 spike 判分逻辑是 `if (value === '2')`）、发布硬门 `_require_published`（无人点发布一律 409）、非 make-ten 题型无 LLM key 即 capability gap。**所有绿灯都来自测试 fixture，不是产品链路。**
3. **承载形态法律死锁**（产品经理核实）：微信 web-view 业务域名**个人主体不可配置**；教育小程序为定向准入类目；`127.0.0.1` 在真机上结构性打不开。**核心 Gate 课堂在当前主体资格下永远无法上线。**
4. **投入结构倒挂**：治理外围（admin 2089 行 + 题库 1109 + 报告/画像）≈ 3635 行 vs 教学主循环 ≈ 2346 行；文档 321MB vs 源码 1.9MB（**169:1**）；原型 v4 2817 行 vs 真实小程序 109 行。
5. **流程反迭代**：13 条护栏中 8 条工程上无法自动验证，536 行开发规范 + 展示确认门 + 每任务约 40 个必填字段 → 改一行代码的文档固定成本 30–60 分钟，且无 CI 兜底。

**修法不是更努力地写代码，而是四件事：换形态（小程序→Web H5）、砍范围（46 功能点→8）、降门禁（发布门禁 5→2、护栏 13→5）、改目标（产品→实验装置）。**

## 1. 各视角核心结论

### 1.1 市场（PM·许清楚，2026 年数据已联网核实）

- 赛道巨大但免费大厂碾压：豆包爱学 MAU 1943 万且全免费，"分步引导 + 关键节点反问 + 智能板书"已成标配——**"先想后看 + 可交互讲解"是入场券，不是护城河**。
- 家长付费的真实标的是"可控感"（学习机均价 3635 元）与"替我选"（教辅 1024 亿），两者都不是极小团队能提供的；"讲得好"的市价已归零。
- 政策面多重利空：教育 App 备&#x6848;**&#x20;+ 教培小程序定向准入（个人主体不可为）、网信办"清朗·未成年人网络保护"专项行动直指"AI 创设不良人设角色"——C16 成长挚友 / C17 AI 形象是负资产，必须立即删除。**
- **商业模式自相矛盾：首版免费、商城 P2，46 个功能点没有一个为收钱服务，却承担全部合规成本。**

### **1.2 架构（架构师·高见远）**

- 技术栈三分类：**必需 8 项 / 可延后 13 项 / 应立即删除 12 项依赖 + 约 1400 行死代码**（AgentScope 全仓仅 3 行 import、宣称的 asyncio.gather 零命中；S3/MinIO 抽象生产消费者为 0；5 个零 import 模块；5 张零引用表；`app/agents/__init__.py` 声称 5 个 agent 实际 0 个类）。
- 启动摩擦是体感根源：看到第一帧画面需 **5 容器 + 3 进程 + 1 次人工后台点击**，8 步里 6 步与教学无关 → 单人反馈回路小时级 → 迭代退化为文档迭代（38 commit 中 20 个是 `docs:`）。
- 横向铺开 vs 纵向打通：96 端点中 46 个属于运营后台；七个域同时"完成"，没有一个域端到端打通。**每个域完成 80%，整体是 0%。**
- 包级循环依赖 6 组（reports↔questionbank/points/profile、learning↔admin_api、core↔admin_api）+ router import router 反模式。

### 1.3 实现（工程师·寇豆码，全部实测）

- 归档内核**确实恢复且真实**：无 `pass`/`TODO` 桩（仅 1 个 1 行占位文件）；对称性结论与架构师互补——**代码没有骗人，骗人的是"验收通过"与"产品可用"之间的等号**。
- 可演示边界：演示的是"服务端 + 管理后台 + 播放器"；Redis 未起（异步腿停在 QUEUED）、无 README/CI/一键启动、**52 个文件未提交**（当前可跑状态依赖未入库改动）。
- 主链路 12 环中 1–11 环 real（第 3 环进程未验证），**第 12 环（正式客户端入口）是 stub**。

## 3. 修正方向（按优先级，可直接执行）

### P0-0 真实用例诚实审计（新增，最高优先级，当天完成）

把 demo `make-ten-16-plus-8` 之外的任意一道题（如 `23+9`）手工喂一次全链路，**记录它在哪一层断掉**（意图识别？skill 检索？无 LLM key？发布门？）。在此之前不新增任何功能或文档——因为我们至今不知道，除了那道答案被硬编码进 fixture 的题（`make_ten.build({'a':16,'b':8,'k':2})` 的 `k=2` 即正确答案）之外，**还有没有第二道题能跑通**。

### P0-1 形态：停止小程序路线，主线改 Web H5（对应 RC1/RC2）

- prototype-v4 已是 H5（2817 行，浏览器实测通过），绕开小程序主体资格、备案、业务域名、审核上架全部前置条件。
- 保留 `/static/lesson.html` 由 FastAPI StaticFiles 同源挂载；未来要小程序时用 web-view 套壳（改 2 行 URL，届时需企业主体）。
- **以 `projects/app/player`（Playwright 9/9）为基础做数据驱动课堂页**；prototype-v4 的 `:root tokens` 继续作为视觉合同（护栏 11 保留部分）。

### P0-2 架构：砍到 1 进程 + 1 个 SQLite 文件 + 1 个静态课堂页（对应 RC3/RC5）

| 改造 | 内容                                                                                                                                                                                         | 量      |
| -- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------ |
| A  | 进程内生成为默认（`AIEDU_INLINE_WORKER=1`），同进程跑 run_pipeline + publish                                                                                                                              | ≈60 行  |
| B  | **发布摩擦 CLI 化**：保留 `_require_published` 与 ReviewRecord 语义完全不动，把"写 ReviewRecord"从"后台 Web 逐个点"降级为 `python -m tools.publish <lesson_id> <revision>`（单人、一条命令、可审计）。真正阻塞演示的是 UI 摩擦，不是审核语义（修订见 §7） | ≈30 行  |
| C  | 课堂页数据驱动：`expectedFor` 硬编码三类 → 读 `node.response.expected`；支持 number/choice/observe；作答走已写好但从未被调用的 `POST /v1/activities/{id}/attempts`                                                        | ≈300 行 |
| D  | `borrow-ten`、`fraction-equal-parts` 落成确定性 Python 模板（照抄 make_ten.py 写法）→ **零 LLM 覆盖三类题型**                                                                                                   | ≈250 行 |
| E  | 删 12 个依赖 + 约 1400 行死代码（AgentScope/boto3/4×OTel/S3 抽象/domains registry/5 张零引用表…）；PG→SQLite（`db.py:16` 已有分支）                                                                                 | 负工作量   |

启动目标：`AIEDU_TRACE=0 DATABASE_URL=sqlite:///./data/aiedu.db AIEDU_INLINE_WORKER=1 AIEDU_AUTO_PUBLISH=1 uvicorn app.api.main:app` **一条命令、0 容器、1 进程**。

### P0-3 范围：46 功能点 → 8（对应 RC4）

- 保留：C2 个性化课堂（主线核心）、C5 足迹最小版（回看刚才那节课）、C8 单孩身份、F1'/F2'/F3' 最小版（一个同意勾选 + 单孩建档 + 1 条证据报告）、A1 单人登录、A3 内容审核降级版。
- 砍 36 项（含立即删除的 C16 成长挚友 / C17 AI 形象——监管负资产；C3 拍题 OCR——备案红线 + 冷启动准确率弱，改手输）。
- 全部砍掉/延后项写入一个 `FUTURE.md` 封存，不再进入任何任务包。

### P0-4 门禁与护栏：发布门禁 5→2，护栏 13→5（对应 RC5）

- 发布摩擦按 P0-2 的 B 实现（CLI 发布，**护栏 5 语义不动**：`verified` + 人工确认两条件保留，只是确认动作从 Web UI 降为命令行）。
- 护栏**坚持 5 条**：1 先想后看（服务端过滤为体）、5 AI 输出≠已审核（verified 语义不弱化）、6 不编造、8 未成年人保护（勾选 + 撤回 + 最小收集）、12 不发明来源。
- **简化 3 条**：2 证据四级→两级（independent/assisted）、9 砍系统参数后台化（env 足够）、11 layout 保留 48px/一屏一任务/tokens，阻断降为发布前检查。
- **降级 TODO 5 条**：3（无 OCR 自动失效）、4（skill 来源透明延后）、7（无积分自动失效）、10（动画同源跑通后收敛）、13（画像引擎为未来设计）。
- **把不可验证的护栏换成 2 条 CI 可执行断言**：① answer-filtered 返回的 spec 中未解锁节点 `response.expected` 必须为 null（一条断言守住护栏 1）；② 课堂页所有可点元素 ≥48px（一条 Playwright 断言守住护栏 11 一半）。其余降为"设计原则"。
- 开发规范 536 行压缩到 ≤2 页可执行清单；任务文档 40 字段 → 一张 TODO 表。

### P1 目标重定位：产品 → **单点实验装置（路线丙）**（对应 RC6）

- 承认当前能力边界：**宣称 = "凑十法一个知识点的完整闭环样本"**，不是"幼小衔接到初中的学习路线"（后者与实际可交付覆盖面差约 3 个数量级——`strategies/` 只注册了 make_ten 一个确定性模板）。
- 新目标：**跑通闭环 + 拿到 20 个真实孩子的行为数据**，验证"先想后看能否产出可判定的差异化证据"。
- 拿到数据后再决策：是否值得为企业主体 + 教育备案付费、是否存在真实留存差异。所有 Roadmap 按此重排。

### P1 工程卫生（立刻做，半天）

- 提交工作树里 **52 个未入库文件**（当前可跑状态依赖它们）。
- 写 1 页 README + 一键启动脚本 + 最小 CI（pytest + 2 条护栏断言）。
- 清理 `docs/memory/research/` 下的第三方仓库克隆与大 gif（321MB → 应 <5MB），移出主仓。

## 7. 修订补充（PM 复核架构证据后的收严，2026-10-20）

### 7.1 验证剧场（比资源错配更致命，列为 RC7）

项目已形成一套**自我证明的闭环，每一层的"通过"都由上一层替它兜底**：

| 层        | 证据                                                                      | 给出的正反馈          |
| -------- | ----------------------------------------------------------------------- | --------------- |
| H5 spike | 判分逻辑 `if (value === '2')`；`?auto=1` 参数**自动模拟孩子点击正确答案**                  | "课堂交互/孩子操作验证通过" |
| E2E 旅程   | `make_ten.build({'a':16,'b':8,'k':2})`——**正确答案 k=2 是人事先填进 fixture 的入参** | "学习闭环验证通过"      |
| E2E 治理   | 手工 `_mark_published()` 绕过流水线                                            | "治理旅程验证通过"      |
| 原型 v4    | state.test 42/42、verify.cjs PASS（只测原型自己）                                | "原型验证通过"        |
| 后端       | 210 pytest passed（不证明端上可用）                                              | "域验收通过"         |

**没有任何一层的"通过"要求"一个真实孩子输入一道他自己的题"。** 这条链路从未承载过任何一道"未知"的题。错配会被人发现，验证剧场不会——因为它每层都在给正反馈。这正是"210 个测试全绿、9 个域已实现，产品却无法使用"的完整解释。

### 7.2 定位收严：自助 AI 家教在当前架构上不成立

两条硬约束咬合成死结：① `_require_published`（`learning/service.py:104`）要求每条 revision 有人工发布记录 → 自助出课在架构上不可实现；② `strategies/` 只注册 make_ten，其余 skill 只是塞进 prompt 的 Markdown → 零 LLM 自动出课覆盖面 = **1 个知识点**。而产品宣称覆盖"幼小衔接到初中"。**宣称与能力差约 3 个数量级——产品叙事建立在一条从未存在的能力上。**

三条路线：甲"自助 AI 家教"（需放宽门禁+重写内核，与护栏 5 冲突，不可行）；乙"教研配送"（1 人产能每周个位数节课，不可行）；**丙"单点实验装置"（宣称=凑十法闭环样本，鸿沟直接消失）——采纳**。

### 7.3 修法四字诀

**降宣称**（K12 路线→凑十法闭环）、**换形态**（H5）、**砍范围**（46→8）、**改摩擦**（CLI 发布，不动护栏 5 语义）。
